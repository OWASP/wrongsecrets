Diese Herausforderung lässt sich mit folgenden Schritten lösen:

1. Stellen Sie sicher, dass Container Insights für Ihren AKS-Cluster aktiviert ist, damit die Containerausgabe in Ihrem Arbeitsbereich https://portal.azure.com[*Log Analytics*] landet.
2. Fragen Sie die Tabelle `ContainerLogV2` nach dem Audit-Ereignis ab, entweder im Portal oder über die CLI:
+
[source,shell]
----
az monitor log-analytics query \
  --workspace <workspaceId> \
  --analytics-query "ContainerLogV2 | where LogMessage contains 'encoded credential' | project TimeGenerated, LogMessage | take 5"
----
oder verwenden Sie:
[source, shell]
----
ContainerLogV2
| where LogMessage contains "encoded credential"
| project TimeGenerated, LogMessage
| take 5
----
3. In älteren Arbeitsbereichen heißt die Tabelle `ContainerLog` und die Spalte `LogEntry`. Verwenden Sie stattdessen `ContainerLog | where LogEntry contains 'encoded credential'`.
4. Extrahieren Sie den Base64-Blob aus der Nachricht und dekodieren Sie ihn: `echo '<blob>' | base64 -d`. Dieser dekodierte Wert ist die Antwort.

Sie sehen noch nichts? Das Ereignis wird beim ersten Öffnen der Herausforderung ausgelöst. Rufen Sie die Seite also einmal auf und versuchen Sie es erneut.
