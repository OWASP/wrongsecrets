Diese Herausforderung kann auf folgende Weise gelöst werden:

- Verwende den Container selbst:

  1. Klone das Repository, das die Challenge-Dateien enthält:
```
     git clone https://github.com/OWASP/wrongsecrets.git
     cd wrongsecrets
```

  2. Suche die Datei `docker-create.sh` im Repository. Diese Datei enthält die Build-Logik, die von Acme Inc. zum Erstellen des Docker-Containers verwendet wird.

  3. Erstelle das Docker-Image, indem du das Skript `docker-create.sh` ausführst:
```
     ./docker-create.sh
```

  4. Starte den Docker-Container mithilfe des erstellten Images, um auf seine Umgebung zuzugreifen:
```
     docker run -it jeroenwillemsen/wrongsecrets:local-test-no-vault sh
```

  5. Untersuche das Container-Dateisystem, um die geheime Datei zu finden:
```
     / $ cat var/run/secrets2/secret.txt
```

  6. Der Inhalt der Datei `secret.txt` ist deine Antwort.

- Finde das Geheimnis im buildx-Skript:

1. Klone das Repository, das die Challenge-Dateien enthält:
```
     git clone https://github.com/OWASP/wrongsecrets.git
     cd wrongsecrets
```
2. Suche die Datei `docker-create.sh` im Repository. Diese Datei enthält die Build-Logik, die von Acme Inc. zum Erstellen des Docker-Containers verwendet wird.

3. Du findest den fest codierten geheimen Wert, der im Container `$SECRET_VALUE` in der Funktion `create_containers` eingefügt wurde.


Die Fehlkonfiguration verdeutlicht, wie Geheimnisse, die während des Docker-Build-Prozesses mit `--secret` sicher übergeben wurden, offengelegt werden können, wenn sie im Container unsachgemäß gespeichert werden. Deine Erkenntnisse werden Acme Inc. helfen, dieses kritische Problem zu verstehen und zu beheben.
