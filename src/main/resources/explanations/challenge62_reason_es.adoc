=== Por qué importa el Desafío 62: Escalada de privilegios de MCP a través de la cuenta de servicio de Google

**El problema:**

Los servidores MCP (Protocolo de Contexto de Modelo) se utilizan cada vez más para dar acceso a los asistentes de IA a servicios y fuentes de datos externos. Cuando estos servidores se configuran con cuentas de servicio o claves API que tienen permisos más amplios que el usuario que realiza la llamada, crean un peligroso vector de escalada de privilegios.

Este desafío demuestra la violación del **Principio de mínimo privilegio**: la cuenta de servicio de Google del servidor MCP tiene acceso a un documento restringido de Google Drive, pero el servidor otorga ese acceso a *cualquier persona que llame* sin verificar si dicha persona está autorizada a ver el documento.

**El escenario del mundo real:**

1. Un desarrollador crea un servidor MCP para ayudar a un asistente de IA interno a acceder a los documentos del equipo en Google Drive.
2. Se concede a la cuenta de servicio acceso de lectura a un documento confidencial.
3. El desarrollador no implementa ninguna verificación de autenticación o autorización del llamante en las herramientas MCP.
4. Cualquiera que descubra el punto final de MCP ahora puede leer documentos a los que no debería tener acceso, utilizando de hecho la cuenta de servicio como un proxy para la escalada de privilegios.

**Por qué esto es peligroso:**

- **Escalada de privilegios**: Quienes llaman obtienen los permisos de la cuenta de servicio, no los suyos propios.
- **Sin registro de auditoría**: Es posible que el acceso a través de la herramienta MCP no se registre con la identidad de la persona que realiza la llamada.
- **Amplia superficie de ataque**: Cualquier cliente MCP (legítimo o malicioso) puede invocar la herramienta.
- **Explotación asistida por IA**: Los agentes de IA conectados a este servidor MCP ejecutarán la herramienta automáticamente cuando se les indique, lo que amplifica el riesgo.

**Cómo solucionarlo:**

1. **Autenticar a los llamantes de MCP**: Requerir un token de autenticación en el punto final de MCP y verificar la identidad del llamante antes de ejecutar las herramientas.
2. **Autorizar a nivel de herramienta**: Compruebe si el usuario autenticado tiene permiso para acceder al recurso solicitado antes de llamar a la cuenta de servicio.
3. **Limita el alcance de los permisos de la cuenta de servicio**: La cuenta de servicio debe tener únicamente los permisos mínimos necesarios para casos de uso legítimos.
4. **Auditar todas las invocaciones de herramientas**: Registre la identidad del llamante junto con cada llamada a la herramienta para que se pueda revisar el acceso.
5. **Prefiera la suplantación de identidad a las credenciales compartidas**: utilice credenciales específicas del llamante o intercambio de tokens en lugar de una única cuenta de servicio compartida.

**Notas de implementación de WrongSecrets:**

- El análisis de las respuestas a los desafíos utiliza contenido etiquetado (`<secret>...</secret>`) y almacena en caché el valor extraído para optimizar su consumo de memoria.
- La recuperación de documentos de MCP utiliza una caché limitada para restringir las solicitudes salientes repetidas, conservando al mismo tiempo el documento predeterminado configurado.
