=== Warum das Speichern von Geheimnissen in .gitignore ein Sicherheitsrisiko darstellt?

Entwickler aktualisieren regelmäßig Konfigurationsdateien wie `.gitignore`, wobei gelegentlich sensible Informationen wie Passwörter, Tokens oder wichtige Dateipfade unberücksichtigt bleiben. Diese Geheimnisse bergen, selbst verschlüsselt, Risiken:

- Angreifer könnten die Geheimnisse entdecken und entschlüsseln.
- Vergessene Geheimnisse in öffentlichen Akten deuten auf mangelhafte Sicherheitsvorkehrungen und ein schwaches Geheimnismanagement hin.

Diese Herausforderung verdeutlicht die Wichtigkeit von Code-Reviews und der Sicherstellung, dass Geheimnisse niemals versehentlich eingecheckt oder zurückgelassen werden.

Was Sie stattdessen tun sollten:
- Verwenden Sie `.gitignore` nicht als Ort zum Speichern von Geheimnissen. Bewahren Sie Zugangsdaten in einem Secrets Manager auf; falls die lokale Entwicklung eine Datei erfordert, halten Sie sie fern von der Versionsverwaltung und schränken Sie deren Dateisystemzugriff ein. Durchsuchen Sie das Repository nach versehentlichen Offenlegungen.
- Falls ein Geheimnis committet wurde, entfernen Sie es aus der Datei und rotieren oder widerrufen Sie es; das Löschen in einem späteren Commit entfernt es nicht aus dem Git-Verlauf.
