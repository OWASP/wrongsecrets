*Why you should not use localStorage for secret information*

LocalStorage persists information across sessions and is easily accessible by javascript. This means there are various ways to obtain any secret information stored in it.

There are various ways to prevent leaking secrets here:
- If you don’t have to: don’t store the secret with the client: keep it on the server.
- SessionStorage is also accessible to JavaScript, so it does not protect secrets from cross-site scripting. For browser sessions, prefer an opaque session identifier in a `Secure`, `HttpOnly`, `SameSite` cookie, with the session state kept server-side.
- Do not rely on client-side encryption for a secret the client must use; the client also needs access to the decryption key. For cross-domain flows, use a server-side exchange or a short-lived, narrowly scoped token instead of storing a reusable secret in browser storage.
