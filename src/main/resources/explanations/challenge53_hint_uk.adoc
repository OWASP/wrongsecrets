За замовчуванням завдання виконується без налагоджувального сайдкара. Ваша мета — проаналізувати бінарний файл, що працює всередині поду, та розкрити секрет.

Цю проблему можна вирішити, виконавши такі кроки:

1. Розгорніть завдання без коляски:
```
   kubectl apply -f k8s/challenge53/secret-challenge53.yml
```
   Перевірте, чи працює pod:
```
   kubectl get pods
```

2. Зрозумійте, що сам по собі pod не забезпечує можливостей налагодження. Тепер замініть розгортання на таке, що включає сайдкар:
```
   kubectl apply -f k8s/challenge53/secret-challenge53-sidecar.yml
```

3. Запустіть контейнер налагодження, підключений до запущеного pod:
```
   kubectl exec -it <pod-name> -c sidecar -- /bin/sh
```

4. Перейдіть до спільного каталогу, де зберігається бінарний файл:
```
   cd /shared-data
```

5. Використайте `gdb` для перевірки бінарного файлу та його запуску:
```
   gdb wrongsecrets-challenge53-c-linux
   run &
```

6. Знайдіть адресу пам'яті секретного коду:
```
   print &secret
   x/s <memory-address>
```

Аналізуючи пам'ять, ви розкриєте жорстко закодований секрет, що зберігається в двійковому файлі.
