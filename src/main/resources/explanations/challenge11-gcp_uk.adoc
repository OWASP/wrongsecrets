=== Менеджер секретів GCP, частина 3

У нашому кластері GKE є обліковий запис служби для робочих навантажень, який зіставляється з обліковим записом служби в Kubernetes.

На жаль, розробники використовували лише один обліковий запис служби GCP для прив’язки до кількох облікових записів служби K8s. Це означає, що різні pod можуть отримати доступ до наших секретів...

Спробуйте налаштувати `wrongsecret-3` за допомогою pod з обліковим записом служби `default` у просторі імен за замовчуванням.


Підказка: Ви можете використовувати завдання із зображенням `gcr.io/google.com/cloudsdktool/cloud-sdk:latest` та використовувати командний рядок `gcloud`.
Див. https://cloud.google.com/secret-manager/docs/creating-and-accessing-secrets#a_note_on_resource_consistency [доступ до секрету] для отримання довідки.
