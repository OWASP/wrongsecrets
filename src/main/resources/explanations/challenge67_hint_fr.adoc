Vous pouvez relever ce défi en suivant les étapes suivantes :

1. Trouvez le groupe de journaux du conteneur WrongSecrets dans https://console.aws.amazon.com/cloudwatch/[*CloudWatch Logs*]. Avec EKS configuré à partir du dossier `aws`, les journaux du pod sont envoyés vers un groupe de journaux portant le nom du cluster, par exemple `/aws/containerinsights/<clustername>/application`.
2. Interrogez le groupe de journaux pour l'événement d'audit, par exemple avec CloudWatch Logs Insights :
+
[source,shell]
----
aws logs start-query \
  --log-group-name "/aws/containerinsights/<clustername>/application" \
  --start-time $(($(date +%s) - 3600)) \
  --end-time $(date +%s) \
  --query-string 'fields @message | filter @message like /encoded credential/'
----
Remarque : dans cet exemple, l'application a généré le secret au cours de la dernière heure, donc si elle est en fonctionnement depuis plus longtemps : sélectionnez une heure de démarrage plus longue !
3. Vous pouvez également le suivre directement : `aws logs tail "/aws/containerinsights/<clustername>/application" --follow --filter-pattern "encoded credential"`.
4. Extrayez le blob Base64 du message et décodez-le : `echo '<blob>' | base64 -d`. La valeur décodée est la réponse.

Vous ne voyez toujours rien ? L’événement est déclenché lors de la première ouverture du défi. Veuillez donc consulter la page une première fois, puis relancer la requête.
