Wie im Text der Aufgabe angegeben, suchen wir im Java-Code nach einem Geheimnis namens `password`. Aber wie finden wir es?

Diese Herausforderung lässt sich durch folgende alternative Lösungsansätze bewältigen:

1. Sobald der Quellcode verfügbar ist, können Sie fest codierte Zeichenketten finden, indem Sie den Code durchsuchen. Grep kann Ihnen dabei helfen, da es in großen Textblöcken nach Mustern sucht. Gehen Sie wie folgt vor, um die Antwort zu finden:
- Öffnen Sie ein Terminal, auf dem https://man7.org/linux/man-pages/man1/grep.1.html[*grep*] und https://git-scm.com/[*git*] installiert sind.
- Klonen Sie das Repository mit `git clone https://github.com/OWASP/wrongsecrets`.
- Navigieren Sie zum Java-Code, in dem die Überprüfung auf die richtige Antwort stattfindet: `cd src/main/java/org/owasp/wrongsecrets/`.
- Verwenden Sie grep rekursiv, um nach der Passwortzeichenkette zu suchen: `grep -r password`.

2. Ein automatisiertes Tool wie https://github.com/awslabs/git-secrets[*Git-secrets*] kann oft hilfreich sein. In diesem Fall muss es mit einer spezifischen Regel eingerichtet werden:
- Klonen Sie das Repository mit `git clone https://github.com/OWASP/wrongsecrets`.
- Folgen Sie den Anweisungen unter https://github.com/awslabs/git-secrets[hier], um Git Secrets zu installieren.
- Füge einen neuen Scan hinzu, um nach der Zeichenkette `git secrets --add 'password\s*=\s*.+'` zu suchen.
- Führen Sie nun den Scan mit dem Befehl `git secrets --scan` aus.

3. Wenn der Quellcode nicht verfügbar ist, versuchen Sie, die eigentliche Anwendung zu beschaffen, um sie per Reverse Engineering zu analysieren. Die Anwendung ist in diesem Fall eine JAR-Datei, die aus Java-Klassendateien und einigen Ressourcen besteht.
- Folgen Sie den Anweisungen unter https://docs.docker.com/engine/reference/commandline/cp/[der Docker-Dokumentation], um die JAR-Datei vom Stammverzeichnis des Containers in Ihr lokales Dateisystem zu kopieren.
- Öffnen Sie die JAR-Datei unter https://java-decompiler.github.io/[*JD-GUI*] oder https://github.com/skylot/jadx[*jadx-gui*] und suchen Sie nun nach dem `String password`!

4. Sie können das Repository mit https://github.com/trufflesecurity/trufflehog[*Trufflehog*] scannen.
- Klonen Sie das Repository mit `git clone https://github.com/OWASP/wrongsecrets`.
- Folgen Sie den Anweisungen unter https://github.com/trufflesecurity/trufflehog[hier], um Trufflehog zu installieren.
- Befolgen Sie diese Anweisungen, um die Datei https://github.com/trufflesecurity/trufflehog/blob/4afc224c635d10e732119f715f93788af1502ce4/examples/README.md[generic detector] herunterzuladen.
- Laden Sie den generischen Trufflehog-Detektor herunter: `wget https://raw.githubusercontent.com/trufflesecurity/trufflehog/main/examples/generic.yml`.
- Scannen Sie die Dateien mit `trufflehog filesystem --config=$PWD/generic.yml . | grep password`; das Passwort befindet sich in der Ausgabe.

5. Alternativ können Sie das ältere Trufflehog 2 verwenden:
- Python und pip3 müssen installiert sein. Führen Sie anschließend `pip3 install trufflehog` aus, um Trufflehog 2 zu installieren.
- Durchsuchen Sie die Dateien mit `trufflehog . | grep password`; das Passwort befindet sich in der Ausgabe.
- Bitte beachten Sie, dass Trufflehog 2 vor mehr als 5 Jahren veröffentlicht wurde (https://github.com/trufflesecurity/trufflehog/tags?after=v3.0.0) und nicht mehr weiterentwickelt wird (https://github.com/trufflesecurity/trufflehog/issues/2328).
