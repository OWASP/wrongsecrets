Standardmäßig wird die Challenge ohne Debugging-Sidecar ausgeführt. Deine Aufgabe ist es, die im Pod laufende Binärdatei zu analysieren und das Geheimnis aufzudecken.

Diese Herausforderung lässt sich mit folgenden Schritten lösen:

1. Die Herausforderung ohne Sidecar bereitstellen:
```
   kubectl apply -f k8s/challenge53/secret-challenge53.yml
```
   Überprüfe, ob der Pod ausgeführt wird:
```
   kubectl get pods
```

2. Beachte, dass der Pod allein keine Debugging-Funktionen bietet. Ersetze nun das Deployment durch ein Deployment, das einen Sidecar enthält:
```
   kubectl apply -f k8s/challenge53/secret-challenge53-sidecar.yml
```

3. Starte den an den laufenden Pod angehängten Debugging-Container:
```
   kubectl exec -it <pod-name> -c sidecar -- /bin/sh
```

4. Navigiere zu dem freigegebenen Verzeichnis, in dem die Binärdatei gespeichert ist:
```
   cd /shared-data
```

5. Verwende `gdb`, um die Binärdatei zu untersuchen und sie auszuführen:
```
   gdb wrongsecrets-challenge53-c-linux
   run &
```

6. Ermittle die Speicheradresse des Geheimnisses:
```
   print &secret
   x/s <memory-address>
```

Durch die Analyse des Speichers wirst du das im Binärcode fest einprogrammierte Geheimnis aufdecken.
