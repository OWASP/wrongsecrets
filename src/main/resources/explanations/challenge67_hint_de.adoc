Diese Herausforderung lässt sich mit folgenden Schritten lösen:

1. Suchen Sie die Protokollgruppe des WrongSecrets-Containers unter https://console.aws.amazon.com/cloudwatch/[*CloudWatch Logs*]. Bei der EKS-Einrichtung aus dem Ordner `aws` werden die Pod-Protokolle in eine Protokollgruppe geschrieben, die nach dem Cluster benannt ist, z. B. `/aws/containerinsights/<clustername>/application`.
2. Fragen Sie die Protokollgruppe nach dem Überwachungsereignis ab, beispielsweise mit CloudWatch Logs Insights:
+
[source,shell]
----
aws logs start-query \
  --log-group-name "/aws/containerinsights/<clustername>/application" \
  --start-time $(($(date +%s) - 3600)) \
  --end-time $(date +%s) \
  --query-string 'fields @message | filter @message like /encoded credential/'
----
Hinweis: In diesem Beispiel wurde das Geheimnis in der letzten Stunde generiert. Wenn die Anwendung also schon länger läuft: Wählen Sie eine längere Startzeit!
3. Alternativ können Sie es direkt mit tail verfolgen: `aws logs tail "/aws/containerinsights/<clustername>/application" --follow --filter-pattern "encoded credential"`.
4. Extrahieren Sie den Base64-Blob aus der Nachricht und dekodieren Sie ihn: `echo '<blob>' | base64 -d`. Dieser dekodierte Wert ist die Antwort.

Sie sehen noch nichts? Das Ereignis wird beim ersten Öffnen der Herausforderung ausgelöst. Rufen Sie die Seite also einmal auf und versuchen Sie es erneut.
