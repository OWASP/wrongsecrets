*Чому не слід використовувати localStorage для секретної інформації*

LocalStorage зберігає інформацію протягом усіх сеансів і легко доступний за допомогою JavaScript. Це означає, що існує кілька способів отримання будь-якої секретної інформації, що зберігається в ньому.

Існує кілька способів запобігти витоку секретів:
- Якщо вам не потрібно: не зберігайте секрет у клієнта: тримайте його на сервері.
- SessionStorage також доступний для JavaScript, тому він не захищає секрети від міжсайтового скриптингу. Для сеансів браузера надайте перевагу непрозорому ідентифікатору сеансу в cookie `Secure`, `HttpOnly`, `SameSite`, зі станом сеансу, що зберігається на стороні сервера.
- Не покладайтеся на шифрування на стороні клієнта для секретного ключа, який має використовувати клієнт; клієнту також потрібен доступ до ключа розшифрування. Для міждоменних потоків використовуйте обмін на стороні сервера або короткочасний токен з вузькою областю дії замість зберігання секретного ключа повторного використання в сховищі браузера.
