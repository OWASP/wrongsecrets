*Warum die Verwendung von Binärdateien zum Verstecken eines Geheimnisses einen Angreifer nur verzögert.*

Mit wunderschönen kostenlosen Reverse-Engineering-Anwendungen wie Ghidra bleibt nicht mehr viel sicher. Jeder, der die ausführbare Datei in Ghidra oder Radare2 laden kann, kann leicht eine Reconnaissance starten und Geheimnisse in deiner Swift-Binary finden.

Swift-Binaries sind – obwohl sie Name Mangling verwenden (du kannst `swift-demangle` verwenden, um Swift-Symbolnamen zu demanglen) – weiterhin anfällig für Reverse Engineering. Geheimnisse, die als Zeichenarrays oder String-Literale gespeichert sind, können im Datensegment der Binary gefunden werden.

Ein Geheimnis mit einem in der Binary eingebetteten Schlüssel zu verschlüsseln und andere lustige Rätsel verzögern einen Angreifer nur und machen das Finden des Geheimnisses geradezu vergnüglich. Beachte, dass das Geheimnis, wenn es von der ausführbaren Datei verwendet werden soll, letztlich im Speicher liegen muss, um ausgeführt zu werden.

Muss ein Geheimnis dennoch in der Binary liegen? Stelle sicher, dass es nur nach Authentifizierung gegen einen Server remote abgerufen werden kann.
