*Pourquoi il est mauvais d'avoir des secrets dans le code front-end*

Lorsque vous exécutez une application mobile sur votre appareil intelligent ou une application monopage (SPA) sur votre navigateur web, évitez d'y intégrer des données sensibles. Un attaquant peut toujours récupérer l'application, la reconstruire et trouver ces données. Demandez-vous plutôt si ces données peuvent être téléchargées en toute sécurité après authentification, ou utilisées d'une autre manière.

*Pourquoi est-il déconseillé d'utiliser des applications monopages ou des applications mobiles pour stocker des secrets clients ?*

Comme vous pouvez le constater, il est facile de détecter n'importe quel secret stocké dans une application monopage ou une application mobile.
Considérez les applications navigateur et mobiles comme des clients publics : n'intégrez jamais de secret client ni d'autres identifiants partagés. Pour OAuth, utilisez le flux de code d'autorisation avec PKCE ; conservez les opérations privilégiées et leurs identifiants sur un backend de confiance.

*Pourquoi l'encodage Base64 n'est pas un chiffrement*

Comme vous pouvez le constater, il était assez facile de décoder le secret du fichier de défi. C'est pourquoi les encodages Base64 et hexadécimal ne doivent jamais être utilisés pour dissimuler un secret. N'utilisez ces encodages que pour garantir la transmission d'une séquence binaire sous forme de chaîne de caractères.
