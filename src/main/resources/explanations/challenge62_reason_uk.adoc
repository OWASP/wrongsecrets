=== Чому Challenge 62 має значення: підвищення привілеїв MCP через обліковий запис служби Google

**Проблема:**

Сервери MCP (Model Context Protocol) все частіше використовуються для надання асистентам штучного інтелекту доступу до зовнішніх сервісів та джерел даних. Коли ці сервери налаштовані з обліковими записами сервісів або ключами API, які мають ширші дозволи, ніж користувач, що викликає, вони створюють небезпечний вектор ескалації привілеїв.

Ця задача демонструє порушення **Принципу найменших привілеїв**: обліковий запис служби Google сервера MCP має доступ до обмеженого документа Google Диска, але сервер надає цей доступ *будь-якому абоненту*, не перевіряючи, чи має абонент право переглядати документ.

**Реальний сценарій:**

1. Розробник створює MCP-сервер, щоб допомогти внутрішньому помічнику зі штучним інтелектом отримувати доступ до командних документів на Google Диску.
2. Обліковному запису служби надається доступ для читання конфіденційного документа.
3. Розробник не реалізує жодних перевірок автентифікації або авторизації абонента в інструментах MCP.
4. Будь-хто, хто виявить кінцеву точку MCP, тепер може читати документи, до яких він не повинен мати доступу, фактично використовуючи обліковий запис служби як проксі-сервер ескалації привілеїв.

**Чому це небезпечно:**

- **Збільшення привілеїв**: Абоненти, що викликають, отримують дозволи облікового запису служби, а не свої власні.
- **Відсутність журналу аудиту**: Доступ через інструмент MCP може не реєструватися з ідентифікатором абонента
- **Широка область атаки**: Будь-який клієнт MCP (легітимний чи шкідливий) може активувати інструмент
- **Експлуатація за допомогою штучного інтелекту**: агенти штучного інтелекту, підключені до цього сервера MCP, автоматично запускатимуть інструмент за вказівкою, що збільшує ризик

**Як виправити:**

1. **Автентифікація абонентів MCP**: Вимагайте токен автентифікації на кінцевій точці MCP та перевіряйте особу абонента перед виконанням інструментів
2. **Авторизація на рівні інструменту**: Перевірте, чи має автентифікований абонент дозвіл на доступ до запитуваного ресурсу, перш ніж викликати обліковий запис служби.
3. **Вузько обмежте дозволи сервісного облікового запису**: сервісний обліковий запис повинен мати мінімальні дозволи, необхідні лише для законних випадків використання.
4. **Аудит усіх викликів інструментів**: Записуйте ідентифікатор абонента разом із кожним викликом інструменту, щоб можна було перевірити доступ
5. **Надавайте перевагу уособленню, а не спільним обліковим даним**: Використовуйте облікові дані абонента або обмін токенами замість одного спільного облікового запису служби.

**Примітки щодо впровадження WrongSecrets:**

- Розбір відповідей на завдання використовує позначений тегами контент (`<secret>...</secret>`) та кешує витягнуте значення для оптимізації використання пам'яті.
- Отримання документів MCP використовує обмежений кеш для обмеження повторних вихідних запитів, зберігаючи при цьому налаштований документ за замовчуванням.
- Відповідні тести:
	- `Challenge62Test`
	- `Challenge62McpControllerTest`
