=== Чому завдання 62 важливе: підвищення привілеїв у MCP через Google Service Account

**Проблема:**

MCP-сервери (Model Context Protocol) дедалі частіше використовуються, щоб надати ШІ-асистентам доступ до зовнішніх сервісів і джерел даних. Коли такі сервери налаштовано на service accounts або ключі API з ширшими правами, ніж користувач, що викликає їх, виникає небезпечний вектор підвищення привілеїв.

Це завдання демонструє порушення **принципу найменших привілеїв**: Google Service Account MCP-сервера має доступ до обмеженого документа Google Drive, але сервер надає цей доступ *будь-кому, хто викликає*, не перевіряючи, чи авторизований викликаючий на перегляд документа.

**Реальний сценарій:**

1. Розробник створює MCP-сервер, щоб допомогти внутрішньому ШІ-асистенту отримати доступ до командних документів у Google Drive
2. Service account надається доступ на читання до конфіденційного документа
3. Розробник не реалізує жодної перевірки автентифікації чи авторизації викликаючих для інструментів MCP
4. Будь-хто, хто виявить кінцеву точку MCP, тепер може читати документи, до яких не повинен мати доступу, — фактично використовуючи service account як проксі для підвищення привілеїв

**Чому це небезпечно:**

- **Підвищення привілеїв**: викликаючі отримують права service account, а не свої власні
- **Немає журналу аудиту**: доступ через інструмент MCP може не записуватися з ідентифікатором викликаючого
- **Велика поверхня атаки**: будь-який MCP-клієнт (легітимний чи зловмисний) може викликати інструмент
- **Експлуатація за допомогою ШІ**: ШІ-агенти, підключені до цього MCP-сервера, виконуватимуть інструмент автоматично за вказівкою, посилюючи ризик

**Як виправити:**

1. **Автентифікувати викликаючих MCP**: вимагати токен автентифікації на кінцевій точці MCP і перевіряти ідентифікатор викликаючого перед виконанням інструментів
2. **Авторизовувати на рівні інструмента**: перевіряти, чи автентифікований викликаючий має дозвіл на доступ до запитуваного ресурсу, перш ніж викликати service account
3. **Обмежити права service account**: service account повинен мати лише мінімальні права, потрібні для легітимних сценаріїв використання
4. **Аудитувати всі виклики інструментів**: записувати ідентифікатор викликаючого разом із кожним викликом інструмента, щоб доступ міг бути переглянутий
5. **Надавати перевагу підміні особистості замість спільних облікових даних**: використовувати облікові дані конкретного викликаючого або обмін токенами замість одного спільного service account

**Нотатки щодо реалізації WrongSecrets:**

- Аналіз відповіді на завдання використовує вміст із тегами (`<secret>...</secret>`) і кешує виділене значення, щоб оптимізувати використання пам'яті.
- Отримання документів MCP використовує обмежений кеш, щоб зменшити повторні вихідні запити та зберегти налаштований документ за замовчуванням.
- Відповідні тести:
	- `Challenge62Test`
	- `Challenge62McpControllerTest`
