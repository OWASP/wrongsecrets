Цю проблему можна вирішити, використовуючи такі способи:

- Використовуйте сам контейнер:

  1. Клонуйте репозиторій, що містить файли завдання:
```
     git clone https://github.com/OWASP/wrongsecrets.git
     cd wrongsecrets
```

  2. Знайдіть файл `docker-create.sh` у репозиторії. Цей файл містить логіку збірки, яку використовує Acme Inc. для створення контейнера Docker.

  3. Зберіть образ Docker, запустивши скрипт `docker-create.sh`:
```
     ./docker-create.sh
```

  4. Запустіть контейнер Docker, використовуючи зібраний образ, щоб отримати доступ до його середовища:
```
     docker run -it jeroenwillemsen/wrongsecrets:local-test-no-vault sh
```

  5. Дослідіть файлову систему контейнера, щоб знайти секретний файл:
```
     / $ cat var/run/secrets2/secret.txt
```

  6. Вміст файлу `secret.txt` і є вашою відповіддю.

- Знайдіть секрет у скрипті buildx:

1. Клонуйте репозиторій, що містить файли завдання:
```
     git clone https://github.com/OWASP/wrongsecrets.git
     cd wrongsecrets
```
2. Знайдіть файл `docker-create.sh` у репозиторії. Цей файл містить логіку збірки, яку використовує Acme Inc. для створення контейнера Docker.

3. Ви можете знайти жорстко закодований секрет, вставлений у контейнер `$SECRET_VALUE` у функції `create_containers`.


Неправильна конфігурація демонструє, як секрети, безпечно передані під час процесу збірки Docker за допомогою `--secret`, можуть стати розкритими, якщо їх неправильно зберігати в контейнері. Ваші висновки допоможуть Acme Inc. зрозуміти та виправити цю критичну проблему.
