= Розкриття секрету конфігурації контейнера розробника

*Чому жорстке кодування секретів у контейнерах розробки є критичним ризиком для безпеки*

Контейнери розробки – це спільні середовища розробки, налаштовані за допомогою `.devcontainer/devcontainer.json`. Оскільки ці файли зазвичай відстежуються в системі контролю версій, жорстке кодування секретів у визначеннях контейнерів розробки створює кілька загроз безпеці:

1. **Доступ для всіх читачів репозиторію**: Будь-хто з доступом на читання до репозиторію вихідного коду (або публічних форків та клонів у проектах з відкритим кодом) може читати секрети, жорстко закодовані у `.devcontainer/devcontainer.json`.
2. **Витік змінних середовища**: Облікові дані, визначені в `containerEnv` або `remoteEnv`, вводяться в кожен процес усередині контейнера, роблячи їх доступними для будь-якого скрипта, дочірнього процесу або діагностичного інструменту, що працює в контейнері.
3. **Постійне в історії Git**: Після фіксації видалення секрету вимагає перезапису історії Git, а застарілі ключі часто залишаються дійсними необмежений час, якщо не виконується ротація.
4. **Важче виявити**: Багато інспекторів секретних файлів та контейнерів досі не виявляють `devcontainer.json`, оскільки він поводиться інакше, ніж `Dockerfile`.

*Виправлення та найкращі практики:*

- **Використовуйте секрети кодових просторів GitHub / секрети контейнера розробки VS Code**: динамічно впроваджуйте секрети через репозиторій кодових просторів/секрети користувачів або налаштування VS Code, а не жорстко кодуйте їх у файлах конфігурації.
- **Використання підстановки локального середовища**: Динамічне посилання на змінні середовища хоста в `devcontainer.json` за допомогою синтаксису `${localEnv:MY_SECRET}`.
- **Використання файлів `.env` з `.gitignore`**: Розміщуйте секрети розробки в локальних файлах `.env`, які явно виключені з контролю версій у `.gitignore`.
- **Впровадження рішень для керування секретами**: отримання секретів під час виконання за допомогою спеціалізованих менеджерів секретів (наприклад, HashiCorp Vault, AWS Secrets Manager, Azure Key Vault, GCP Secret Manager).
